# 發布與驗收

## 發布網站

1. 備份現行網站與主機設定，再將 `website` 內全部檔案及 assets 完整上傳至正式網站根目錄。圖片、字型、robots.txt、sitemap.xml 及全部 HTML 須一起上傳。
2. 正式網域沿用 `https://www.hlaglobal.com.tw/`。若主機另有 HTTP、無 www 或 `/index.html` 別名，請由管理者在主機層設定合適的永久轉址，先核對現有規則，避免轉址循環。本包沒有套用未知主機的伺服器設定。
3. 確認不存在先前測試站留下的全站 noindex、robots 封鎖、驗證牆或登入限制。保留本版特定輔助頁自己的 noindex。
4. 主機須將找不到的網址回傳真正的 HTTP 404，並使用 `404.html` 顯示內容。只有顯示404文字、實際回200的設定不算完成。
5. 新版 HTML 參照的 CSS／JS 帶有版本參數。發布後清除舊 HTML 快取，避免舊頁面繼續引用過期資料；不要長期以不可更新的快取保存 HTML。
6. 在正式網域驗證 Sitemap、Canonical、結構化資料與 Google 後台。管理用的 `documentation` 不必公開上傳。

## 已執行的檢查

- 64 個 HTML 檔名保留，每頁一個 H1、唯一 Title／Description、正確 Canonical、OG 與 Twitter 資料。
- 站內檔案、圖片、srcset 與錨點存在，沒有本次新增的斷鏈。
- 四個靜態列表頁完整提供32篇文章，分頁各自 Canonical；ItemList 與各頁八篇卡片一致。
- 八個服務結構化實體與可見內容對應，32篇文章具主要與適當第二服務的雙向連結。
- JSON-LD 可解析、實體 ID 不重複；Sitemap 與57個可索引頁完全一致。
- 原有法律內文、作者與來源保留；全部原有圖片／字型及主樣式的檔案位元組一致，HTML 圖片比例屬性保留。
- 八類篩選、舊分類參數、分類名稱別名、無效輸入與返回原列表通過程式測試。
- 分析同意、拒絕、本機模式、私人搜尋參數、分類白名單、導航事件與摘要轉換區分通過程式測試。
- 五個 JavaScript 檔案通過語法檢查。

互動回歸測試使用受控 DOM 的 Node VM 執行真實程式，並非瀏覽器端到端或畫面測試。靜態驗證亦不等於 Google Rich Results Test、正式 HTTP 回應或 Google 收錄狀態的驗證。

## 發布後的實機檢查

本次環境沒有可用的瀏覽器驗證能力，以下項目尚未執行：

| 項目 | 檢查內容 |
| --- | --- |
| 桌面與手機版面 | 375、768、1440等代表寬度，確認導覽、服務 H1、新增準備區塊及頁尾沒有溢出或遮擋 |
| 圖片實際顯示 | 首頁主視覺、八大服務圖、文章圖、律師肖像與實景，確認載入及裁切符合原設計 |
| 無 JS 導覽 | 關閉 JavaScript，透過四個文章列表讀取32篇文章，確認服務及作者連結可用 |
| 互動與鍵盤 | 選單、頁籤、FAQ、分類切換、返回全部、搜尋、LINE與複製連結 |
| 聯絡方式 | 電話、LINE、Email、Google 地圖與各交通模式是否正確開啟 |
| 分析選擇 | 同意前不載入分析；拒絕與撤回後不繼續送出；案件與私人搜尋內容不出現在事件 |
| 主機行為 | HTTPS、網域轉址、404狀態、壓縮、快取、字型與圖片內容類型 |
| 搜尋可讀取性 | GSC網址檢查、Google結構化資料測試、Sitemap提交與實際Canonical |
| 效能 | 正式主機測量 Lighthouse 與 Core Web Vitals，不以原始檔檢查推定分數 |
